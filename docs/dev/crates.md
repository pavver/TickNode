# Crates

Developer reference split out of [AGENTS.md](../../AGENTS.md).
Keep it current when the described code changes.

- `ticknode-shared` — `lib.rs` re-exports every serialized type: `values.rs` (`DataValue`, `DataType`, `NumberValue`, value type names), `definitions.rs` (node/pin definitions, inline values and split pins), `graph.rs` (graph models and node IDs), `protocol.rs` (editor messages and traces), `manifest.rs` (`Capability`, `PluginManifest`), plugin settings (`plugin.rs`), plugin-defined types (`types.rs` with `types/conversion.rs`: `TypeDefinition`, `TypeRegistry`), `variables.rs` (`VariableScope`, `VariableKey`, `Variable`, `VariableLookup`, `VariableChanges`, `VariableCommand`, limits & validation), `sheets.rs` (`SheetId`, `SheetInfo`, `SheetSummary`, limits & validation), and `ui_message.rs` (`UiMessage`, `Translations`, `fluent_slug`). `text.rs` with `text/duration.rs` parses human-entered durations and values. `template.rs` provides pure MiniJinja template analysis (`variables`, `validate`, `CompiledTemplate`, `render`, `plain`, `TemplateError`), `template::highlight` (hand-written resilient syntax tokenizer returning contiguous ordered token ranges) and `template::complete` (pure caret completion with type-aware filters, tests, and iterables: variables, struct fields via `TypeRegistry`, `text.`, `loop.`, tag keywords, functions). `formula.rs` provides a pure hand-written formula engine (`formula::{ast, catalog, error, eval, inference, lexer, parser}`: Pratt parser, function catalog, exact integer math, dimension-aware quantity inference). `NodeOutput`, `MathOp` and `LogOp` remain in `lib.rs`. `condition.rs` holds the Match model and input helpers with `condition/{operators,parsing,evaluation,display,error}.rs` (operator tables, parsing, evaluation, text presentation and errors). Extracted tests live in `definitions/tests.rs`, `condition/tests.rs`, `template/highlight/tests/{expressions,literals}.rs`, and integration tests in `tests/behavior/main.rs`.
- `ticknode-core` — `lib.rs` re-exports the public API: `node.rs` (`Node`, `NodeContext`), `error.rs` (`EngineError`), `registry.rs` (`NodeRegistry`), `variables.rs` (`VariableStore`), `engine.rs` (`TickEngine` state and construction with disabled nodes set `disabled: HashSet<NodeId>`, `set_disabled`, `is_disabled`, `set_node_sheet`) with `engine/{nodes,connections,persistence,execution}.rs` (node editing, connections, graph/snippet import/export, tick execution and data pull), `builtin.rs` and `builtin/` (built-in node families, including `builtin/variables/`), `host.rs` (`HostState`: tasks, HTTP, logs, changed variables), `plugin.rs` (plugin records and public re-exports) with `plugin/{bindings,host,runtime,options,node,outputs,convert,loading,lifecycle,catalog,emissions}.rs` (WIT bindings, host imports, instances, `OptionStore`, `WasmNode`, output validation, value/type conversion, loading, enable/disable/settings, editor catalog and tick emissions), `custom_types.rs` (named types), `stub.rs` (stub nodes), `translations.rs` (Fluent resources: core `locales/{en,uk}.ftl`, validation and merging of plugin resources). Extracted unit tests live in `tests.rs` (with `tests/{engine_execution,match_execution,builtin_contracts,legacy_nodes,mutation_contracts}.rs`), `tests/variables.rs`, and `plugin/tests.rs`.
- `ticknode-server` — axum: `/ws` (WebSocket, postcard) plus the editor's static files. `main.rs` owns startup and routing, with integration tests in `main/tests/mod.rs` (`main/tests/{session,settings,telemetry}.rs`). `actor.rs` runs the engine on its own OS thread (ticks and commands sequentially, no locks), with editor command handling in `actor/commands.rs` (with `actor/commands/{connections,nodes}.rs`, plugin commands in `actor/plugin_commands.rs`, variable commands in `actor/variables.rs`), sheet operations and summaries in `actor/sheets.rs`, and tests in `actor/tests.rs` (with `actor/tests/history/{batches,broadcast,undo_redo}.rs`); `storage.rs` — manages scenario sheets (`data/sheets.json`, `data/sheets/<id>.json`, migration from legacy `graph.json`, and trash directory); `plugins.rs` — discovery of `data/plugins/*.wasm` and plugin state, with config persistence and environment overrides in `plugins/config.rs` and tests in `plugins/tests.rs`; `ws.rs` — an editor session tracking `open_sheet` and filtering events.
- `ticknode-editor` — the editor: `state.rs` (`Editor`, a `Copy` set of signals including `sheets` and `open_sheet`) with `state/{graph,messages}.rs` (graph queries, `apply(ServerMessage)`, and minimal sheet bootstrap), `i18n.rs` (Fluent bundles, locale and `t!`) with `i18n/{definitions,values}.rs` (server-provided definition labels, UI messages, value and condition presentation), `connection.rs` (WebSocket and reconnects), `canvas.rs` (canvas composition) with `canvas/{camera,interaction,node,pins,wires,selection,paste}.rs` (viewport, pointer gesture state, node view, pin controls, wires, selection bounds and paste preview) and `canvas/interaction/motion.rs` (with `canvas/interaction/motion/finish.rs`, gesture updates and completion), `panels.rs` (public re-exports) with `panels/{palette,resources,variables,help,execution,console,formatting}.rs` (palette with `panels/palette/drag.rs`, resources, variables placeholder, node help hover card, execution traces, console and display helpers), `node_context.rs` (node context menu), `plugins_panel.rs` (plugin state, toggle, permissions, settings form), `resource_menu.rs` (action picker for dropped/clicked resources), `inline.rs` (input value fields) with `inline/properties.rs` (node property rows) and `inline/template_field.rs` (in-place template editor with `template_field/{caret,preview,completion,hover,highlight}.rs`), `match_editor.rs` (Match state and body) with `match_editor/{inputs,cases}.rs` (input rows and case/condition rows), `picker.rs` (dynamic property field, filtering and placement) with `picker/popup.rs` (popup lifecycle and keyboard navigation), `ui.rs` (design-system components), `geometry.rs`. Extracted unit tests live in `{categories,geometry,i18n,inline,match_editor,panels/resources,picker,plugins_panel}/tests.rs` (with `geometry/tests/{layout,routes}.rs` and `i18n/tests/{audit,labels,resources}.rs`) and `inline/template_field/tests.rs`.
- `ticknode-plugin-sdk` — the plugin SDK (wit-bindgen): `lib.rs` keeps bindings and public re-exports; `plugin.rs` defines `Plugin` (with `types()` and `configure()`), `PluginNode` and setting helpers; `events.rs` defines HTTP/task/trigger/output and WebSocket/emission types; `values.rs` provides `StructValue`, `Inputs::field*` and `field*()`; `pins.rs` provides pin builders; `host.rs` provides `host::*`; `export.rs` implements `export_plugin!` and the WIT guest adapter, using conversions in `convert.rs`. `*-plugin` are plugins; `test-plugin` exists only for host tests, with its factory in `lib.rs` and probes in `{execution,settings,typed,websocket}.rs` (execution/isolation, settings/options, custom types and WebSockets).
- `ha-plugin` — the Home Assistant integration (plugin name `home_assistant`, nodes `ha/action` (action/target pickers and snapshotted typed field inputs), `ha/entity` (typed Value/Previous data and Changed pulses), `ha/condition_<kind>` gates for time, sun, zone and async template (In → Yes/No plus Result; shared live state cache and HA-rendered local UTC offset), and `ha/trigger_<platform>` for time, time_pattern, sun, zone, event, homeassistant, mqtt, webhook, calendar, tag, conversation and template; type `ha.state`). It drives the sans-IO `Session` of the external crate `ha-core-client` (git dependency, no `runtime` feature) from `Plugin::tick`: `hub.rs` holds shared state, with `hub/{connection,subscriptions,requests,templates,options,collection,env}.rs` handling the session/tick loop, watchers, one-shot requests, template conditions, option publishing, output mapping and the `Env` trait. Host calls and the clock are injected; `hub/tests.rs` runs the hub with a scripted fake Home Assistant on the host target. `actions.rs` re-exports service discovery, picker filtering/order and the snapshotted action node from `actions/{catalog,options,node}.rs`; `triggers.rs` keeps platform schemas and re-exports `triggers/{config,outputs,node}.rs` (typed configuration, output projection, node lifecycle); `conditions.rs` keeps gate schemas and re-exports `conditions/{evaluation,node}.rs`. `lib.rs` defines the plugin, `runtime.rs` adapts host calls/logging and shared hub access, `entity.rs` defines the entity event source with pure inference/conversion in `entity/value.rs` and HA unit mapping in `units.rs`; `convert.rs` maps states/JSON to `DataValue`, `queue.rs` is the bounded FIFO queue. Extracted inline tests live in `tests.rs` and `{actions,entity,hub}/tests.rs`. The host test `ha_plugin_*` in `ticknode-core/tests/plugins.rs` runs it against a fake HA WebSocket server. Defaults to `ws://homeassistant.local:8123/api/websocket`; the add-on overrides it with the Supervisor endpoint `ws://supervisor/core/websocket` (`TICKNODE_PLUGIN_HOME_ASSISTANT_URL`); the token is a secret setting. `ha/action` persists `skip_unchanged` (yes/no, missing = yes): table-driven effects in `actions/effects.rs` skip the HA call only when every explicit target entity is known in the live cache and already satisfies the effect (Done still fires); while a sent call's targets have no newer cached state (`Live::revision`, 10 s timeout) nothing is skipped, so a quick on→off is never lost. Synthetic `<domain>.set_state` actions add a required Bool State field (true turns on, locks or opens). `actions/inference.rs` types unitless number/input_number values and climate temperatures from a single target entity's unit (snapshotted in `field_units`; legacy Number snapshots unchanged). Missing states clear their output pins; `ha/entity` clears Value/Previous when the selected type cannot represent the state.

- `telegram-plugin` — Telegram bot integration (plugin name `telegram`, category `Telegram`): `lib.rs` defines settings and exports; `schema.rs` defines triggers, actions (including media download), builders, four opaque identifier types and user/message structs; `model.rs` parses updates and projects typed values; `api.rs` builds requests and classifies failures; `runtime.rs` adapts WASI storage, host HTTP and time.
  The sans-IO `hub.rs` with `hub/{polling,updates}.rs` owns authentication, single-flight long polling, offsets, trigger registrations and bounded queues; `directory.rs` with `directory/{learning,options}.rs` owns persistent ID/name lookup; `triggers.rs` with `triggers/filter.rs` handles subscriptions and filtering; `actions.rs` with `actions/body.rs` handles node-owned JSON/multipart HTTP and rate-limit retries; `download.rs` owns Telegram file lookup and save-to-blob downloads; `validation.rs` shares property and markup validation.
  Host tests live in `tests.rs` and the corresponding module `tests.rs` files.
  See the Telegram section and `telegram-plugin/README.md`.
