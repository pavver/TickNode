# Editor

Developer reference split out of [AGENTS.md](../../AGENTS.md).
Keep it current when the described code changes.

Universal Make Object and Break Object nodes translate field labels using the selected struct type's Fluent keys, including canvas pins, help card labels, paste previews, and width measurement.

- Runtime node errors appear as an error icon with translated message, count and age, plus the Error outline; frozen UI takes precedence. Pin/wire hover shows the latest trace value and age; hovering a variable name or struct field inside `text/template` shows the corresponding input pin or field tooltip with its type and latest trace/inline value. The toolbar toggles wire value labels, remembered in `ticknode.show-values`; labels use the To text presentation (`i18n::value_as_text`: UI locale, project display rules, browser time zone); labels follow live positions and route points.
- Arrow keys move the selected nodes, or the selected frame with its contents, by one grid cell (`5 * DU`); Alt moves by `DU`, Shift by five cells (`canvas/nudge.rs`). Presses are previewed locally and a burst separated by less than 400 ms is sent as one `Batch` (one Undo step); pointer presses and other shortcuts flush it first.
- Quick add: double-click empty canvas or press Space/Tab while hovering it; the shared node popup ranks translated catalog entries, promotes up to five browser-local recent types (`ticknode.recent-nodes`), and sends `AddNode` at the snapped opening point. Palette and wire-menu additions also update recents.
- Node resize previews live in `ClientNode::size_preview`; all canvas geometry uses `Editor::layout`. `NodeLayout::sized` distributes extra whole pixels over free String/Multiline property rows and unconnected String input rows (except Match), keeping sockets on the first line and output rows independent. CSS row heights follow layout; grown fields are textareas (Ctrl/Cmd+Enter or blur commits, Esc restores). The corner handle captures the pointer; release sends once, double-click resets, Esc cancels.
- Date-time values are shown, edited and parsed in the browser time zone (`i18n::local_datetime_text`, `value_edit_text`, `parse_local_datetime`; RFC 3339 text keeps its offset); values stay UTC instants. The add-on image installs `tzdata` so the server's `Local` honours the Supervisor's `TZ`.
- Duration inline values (including Constant) use a compact number/text field and localized unit select (`ticks`, `ms`, `s`, `min`, `h`) in the existing row. Bare numbers use the selected unit; explicit duration text overrides it. Non-integral values keep a lossless text representation. Tick display uses Fluent plurals.
- `Editor::timers` follows full `Init.timers` / `Timers` snapshots, timestamping their freshly measured remaining times (a restarted delay may have identical values). Each timed node has an absolutely positioned 5 px bottom bar: CSS animates from remaining/total to zero over the remaining milliseconds, and a counter shows multiple delays. Timer controls do not change node geometry.
- Frozen nodes show translated pin changes in the header tooltip and the node help card; confirmation sends `ConfirmPins` and preserves detached wires and existing layout rows.
- Detached wires follow server events, use old directional rows as anchor fallbacks, and support selection/removal and loose-end reconnection from the live pin. Reconnection sends a connect + `RemoveDetached` batch; cancelling never opens the node menu or removes the wire.
- Wires support grid-snapped route points: double-click a wire to add, double-click a point to remove, drag a point to move, pull a wire sideways past `WIRE_PULL_THRESHOLD` (8 px) to insert and drag a point, or use the wire/point context menu. A pressed point is `Editor::selected_point`: Delete removes that point instead of the wire. `Editor::wire_routes` follows server events with local drag previews; group moves translate routes with both endpoints selected in the same history entry. Snippets preserve and offset internal routes.
- Dropping a wire on the canvas background opens `Editor::wire_menu` at the release point and keeps the pending wire visible. `wire_suggest.rs` ranks default catalog pins by exact type (an adaptive definition's fitting or Any opposite-direction data pin counts as exact), compatibility and Any, omitting pins reachable only through an implicit conversion (Bool → Number), selecting the lowest pin ID at the best rank (match type only picks the pin); titles and category details are translated. `arrange` orders the menu: a "Frequently used" section (up to 5 types, by node count in the graph, then browser-local recents), then every other match grouped by category in palette order, editor-preferred types for the dragged data type first (`PREFERRED_TYPES`: String → `text/template`), then title. `MenuRow.section` draws a divider wherever the section changes (quick add uses it for recent/all). `WireMenuLayer` shares picker filtering, placement, row limit and keyboard decisions; outside press, Esc, camera changes or a missing origin close it. Selection sends `AddNodeConnected`; `Created` selects the node. Dragging from a connected data input still relocates its wire (the input is disconnected and the source output becomes the origin), so dropping it on the background offers nodes for that output.
- Frames (comment boxes) render behind wires and nodes with a translucent fill and header strip (`6 * DU`); the body passes clicks through to the canvas. Key `C` or the toolbar button creates a frame around selected nodes (or 400×240 centered) with `6 * DU` padding (`12 * DU` top) snapped to `DU`. Selecting a frame (`Selection::Frame`) enables Delete (`RemoveFrame`); double-click renames the title, and the header swatch recolors it. Dragging the frame header moves the frame with all nodes, routes and frames fully inside it in one `Batch`; the bottom-right handle resizes it (`MIN_FRAME_W`/`MIN_FRAME_H`..=`MAX_FRAME_SIZE`, snapped to `DU`). Copy, cut, duplicate (Ctrl+D) and paste include the frame and its enclosed nodes; cutting removes both in one Batch.
- The design is the Operator UI design system ([../operator-design-system](../operator-design-system): Leptos components in `web/operator-ui`, specifications in `docs/`, tokens in `tokens/tokens.toml`; see *Project rules*): tokens in `ticknode-editor/styles/base.css` (`:root` / `[data-theme=light]`; the other `styles/*.css` files are linked in cascade order from `index.html`), unit `--du: 4px`, square corners, control states Idle/Selected/Pending/Success/Error (`ui::ControlState`).
- Wires are built from computed pin positions (`geometry.rs`), not measured in the DOM: the constants `DU`, `NODE_WIDTH` / `MATCH_WIDTH` (width — `NodeLayout::width`) and the header/row heights must match the CSS of `.node-header`, `.node-props`, `.pins`, `.pin`. `NodeLayout` gives pin positions and the node size: simple properties (text-typed, except `in:*`) are rows between the header and the pins; in Match, after In, the input rows and the "+ input" row come the case blocks (`case_rows`), each case's exec output sits in its block header, Else in the last row.
- All settings live on the node itself (properties, `*_type` drop-downs, input values, Match conditions, ▶ "run" in the header); there is no side inspector: the `info` icon in the header opens a design-system HoverCard (`panels/help.rs`, `NodeHelp`) with the description, help, frozen pins and the last execution, and a right click opens the node context menu (`node_context.rs`, design-system `Menu`: duplicate, copy, delete the selection). The menu opens one animation frame after the press, so the menu's outside-press listener does not see the press that opened it. The wire context menu adds "Disconnect". Controls on a node must not let `pointerdown` reach the canvas (`stop_on_controls`), or a drag starts.
- A dynamic `class=move || …` overwrites the whole `className`, so do not combine it with `class:x=…` on the same element: build the class as one string.
- Fields that may lose focus after being removed from the DOM read signals via `try_*`. Node signals (`ClientNode`) are disposed lazily (`dispose_later`), and `Init` updates existing nodes in place.
- In `view!`, an attribute expression containing `<` or `>` must be wrapped in `{…}`, or the macro takes it for the end of the tag.
- The editor never changes the graph locally: action → `ClientMessage`, state is updated only from `ServerMessage`s (exception: node positions, node sizes and wire route points while dragged).
- Below 900 px the panels become overlays (`Editor::narrow`).
- **Logo.** The source is `assets/logo/ticknode.svg` (F1 fills; the 1 px inner outline follows the theme text color via `prefers-color-scheme`). `assets/logo/render.sh` (rsvg-convert) writes the PNGs with the light-theme dark outline: `ha-addon/ticknode/{icon,logo}.png`, the editor favicons in `ticknode-editor/assets/`, and `assets/logo/ticknode-<size>.png`; rerun it after changing the SVG. The header mark (`logo.rs`, `styles/logo.css`) inlines the same shapes with a `currentColor` outline and plays one 4 s cycle while connecting or for 4 s after `Executed` traces or a sheet summary reporting a fresh run; it stops only at a cycle boundary (`animationiteration`). `assets/logo/ticknode-animated.svg` is the same mark and keyframes looping forever, used by the README; keep it in sync with `ticknode.svg` and `logo.css`.
- Navigation and screens: URL hash is the source of truth (`#/` = home page, `#/sheet/<uuid>` = sheet page; `parse_route` / `route_hash`). On `Init` with `open_sheet == None`, if the hash names a known sheet, the client sends `OpenSheet(Some(id))`; if unknown or removed, it resets hash to `#/`. `hashchange` sends `OpenSheet`. Canvas shortcuts, clipboard handlers and quick add are inactive on the home page.
- **Home page**: app header ("TickNode", status line, theme and language buttons) with the design-system `NavigationRail` (vertical on desktop, `horizontal` top tabs on narrow screens; short `home-rail-*` labels; the section id is stored in `ticknode.home-section`): **Sheets** (cards in server order with title, multi-line caption, stats, live relative run age, enable switch, inline edit, duplicate, move up/down, and in-page trash delete confirmation; "New sheet" navigates on `SheetCreated`), **Variables** (global and persistent variables), **Plugins** (full-width list of `PluginCard`), **Log** (full-height `Terminal` with clear button), and **Settings** (browser-local Interface preferences: language, theme, show values on wires; server-wide Engine settings: tick length, work budget, formatting language, quantity display rules, validation and Save/Reset).
- **Sheet page header**: back button (`mdi:arrow-left`) navigates to `#/`. Shows sheet title with a muted "Disabled" chip when disabled and the status line below. A pencil button (`toolbar/title.rs`) swaps the title for a design-system TextField: Enter or Save sends `UpdateSheet`, Escape or the close button cancels, an empty title is rejected in place. Actions include canvas tools (undo/redo, palette, show values, fit, frame, console) and theme/language; the Plugins button is on the home page; a help button shows the graph statistics and canvas controls in a hover card.
- Plugin cards (`PluginCard`, on the home page): name, version/author, state chip (`ControlState`: Success — running, Idle — disabled, Error — error with text; a separate "settings error" chip), the enable switch (`Switch`, Pending until the server answers), permissions, a settings form generated from the schema and "Save" → `ConfigurePlugin`; a `configure` error is shown under the form. A secret field is a password input with a "set" placeholder and a "Clear" button; an empty field means `Keep`. A stub node (`NodeInstance.unavailable`) is dimmed, shows "plugin unavailable" and its properties and input values are read-only (CSS `.node.unavailable`).
- Canvas controls: the middle button pans (on touch — a finger on the background), left button on the background draws a selection box (left-to-right — "window", only fully enclosed nodes; right-to-left — "crossing"). Palette: click adds a node, dragging drops it under the cursor.
- Left panel tabs (**Nodes**, **Resources**, **Variables**; `localStorage` `ticknode.left-tab`): the category rail is shown only on the Nodes tab. The Resources tab lists dynamic options grouped by plugin collection (`ticknode.resources-collapsed`), searchable by terms across label, detail and value; dragging or clicking an item creates a configured node via `AddNodeWith` (directly for a single action, or through an action menu popup when multiple actions match `requires_source`).
- **Variables in the editor**: the **Variables** tab on a sheet page shows this sheet's variables, then global, then persistent; the **Variables** section on the home page lists global and persistent variables (`VariablesList`). Searchable by terms across name, value text and type title; values are edited in place (text fields committing on Enter/blur with parse errors shown, bool switch, enum dropdown, duration with units, multiline textarea for long strings; complex types show a truncated preview with an expand toggle). An inline form adds variables with validated names; deleting requires inline confirmation. On a sheet page, dragging a variable onto the canvas or clicking its plus button opens an action menu (Get, Set, When it changes, Delete) placing configured nodes via `AddNodeWith`.
- Node settings clipboard: Shift + right-click copies the node's type, translated title and all stored properties (including from stubs) into `Editor::copied_settings`, suppresses the context menu and logs a translated confirmation. Shift + left-click pastes onto the same type without changing selection; otherwise it toggles selection. Ctrl/Cmd + left-click always toggles selection. Node controls retain their own pointer handling. The pure `node_click_action` owns this decision; Esc clears copied settings in addition to its existing selection/paste behavior.
- Clipboard: `copy`/`cut`/`paste` events (work without HTTPS); a snippet is JSON `{"format":"ticknode/snippet@1","graph":GraphModel}` (`clipboard.rs`). Ctrl+V does not create nodes immediately: the snippet becomes `Editor::pending_paste` and follows the cursor (left button — `ClientMessage::Paste`, right button/Esc — cancel; the middle button pans). A `paste` right after a middle click is ignored: that is Linux's primary-selection paste. The server assigns new IDs and answers the initiator with `Created` to select the pasted nodes.
- The node help card shows a node's last execution from `NodeTrace` (inputs, outputs, fired exec pins, "N seconds ago"). The server sends traces in `Executed` (every telemetry interval) and the latest ones with their age in ms in `Init`; they live only in memory.
- Named types in the editor: `Editor::types`, `geometry::type_color` (the type's `color`, otherwise a hash of the name), `Editor::type_title`; an unconnected enum input is a drop-down (`InlineValue`).
- **Internationalization (`i18n.rs`, Mozilla Fluent).** Locales `en` and `uk`. The editor's own texts live in `ticknode-editor/locales/{en,uk}/ui.ftl` (UI, categories, data types, Match operators, `error-*` keys for engine errors) and are embedded with `include_str!`; texts of nodes, types, categories and plugin settings come from the server (see *Translations*) and are added to the bundles with `set_runtime_translations` (`ui.ftl` ids win on a clash). The active locale is `RwSignal<Locale>` in the Leptos context (`Editor::locale`), stored in `localStorage` (`ticknode.locale`; default — the browser language: `uk*` → `uk`, otherwise `en`). **Every new UI string goes through `t!("key")` / `t!("key", arg = val)` and must exist in both locales.** For node/type/setting texts use `i18n::node_title`, `node_description`, `node_help`, `node_pin_label`, `type_def_title`, `enum_value_title`, `setting_title`/`setting_description`/`setting_option_label`, `category_label`; a `UiMessage` is shown with `i18n::ui_text`. Without a translation the definition's own (English) text is shown. The editor tests check `ui.ftl` syntax, identical key sets in both locales, that every `t!("...")` key exists, and the runtime-resource lookup order.

### Plugin value completion

Template, expression and inline binding fields share hierarchical completion for plugin namespaces, including formatted `text.<namespace>` paths.
The editor indexes only slim catalog keys, titles and icons when a namespace changes, and queries the matching prefix at one level with at most 50 results.
It requests a referenced entry's field tree through `ClientMessage::ValueEntryFields`, deduplicates pending requests and keeps answers in the existing per-entry cache until that namespace changes.
A field answer refreshes the focused completion without requiring another keystroke.
Nested completion, reference diagnostics and bound input contracts reuse `ticknode_shared::effective_type`, declared catalog fields and hidden runtime field metadata.
Diagnostics wait for a missing field tree before treating a field as unknown.
Entity suggestions carry their title and icon, and field suggestions show localized TickNode type titles, including quantity units and list element types.
Bound namespace chips show the entity title, field path and effective type, and flag incompatible destination contracts even when telemetry is unavailable.
Template previews consume only open-sheet namespace telemetry and cached field contracts; trace views retain the same bound source type contracts.
- **Text scaling**: the shell uses Type Units and follows the browser text size; canvas text follows only the canvas zoom, because node geometry (row heights, sockets, widths) is computed in Rust from DU constants (see `docs/plans/ui-redesign.md`, section 6).
