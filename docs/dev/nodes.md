# Nodes and the graph

Developer reference split out of [AGENTS.md](../../AGENTS.md).
Keep it current when the described code changes.

- **Confirmed pins and frozen nodes.** `NodeModel.pins` stores the base pin signature (before split fields). Loading/reviving a node freezes it if a confirmed pin disappeared or changed direction/kind/data type, or an input became required. Names and optional additions do not freeze; legacy graphs without signatures record current pins. Frozen nodes do not execute, poll, receive task results/emissions or yield data until `confirm_pins`; user property/split/settings edits accept their new contract. Signatures survive stub transitions.
- **Detached connections.** Invalid saved/revived pin connections become `GraphModel.detached_connections`, preserving exec/data kind, both endpoints, the changed end (target preferred) and its old directional row. Confirmation keeps them; removing a node drops touching detached wires. Snippets include internal detached wires and remap their IDs on paste.
- A node is recreated from `type_name` + `properties()`; this is the only persistence/copy mechanism (`export_graph`, `load_graph`, `export_snippet`, `import_snippet`). Every configurable node implements `set_property` and `properties()` symmetrically.
- `NodeRegistry::register(creator)` takes the definition from an instance with default properties; definitions are not described separately.
- Pins may depend on properties (`math/expression` derives inputs from the formula's variables; `list/*`, `object/*` take the type from `element_type`/`field_type`).
  `set_node_property` removes connections that became invalid and returns them in `RemovedConnections`.
- **Formula node (`math/expression`).**
  Pure node (cost 1, adaptive, title "Formula").
  Variables in the formula become optional input pins (default 0).
  Pin stability and in-place rename detection mirror `text/template` using hidden `pin_ids` and `next_pin`.
  Legacy graphs without `pin_ids` fall back to alphabetical mapping.
  Input pins adapt individually to physical quantities.
  Output type is inferred from inputs or explicitly selected via `value_type`.
  Syntax errors and runtime faults yield no output and report translated errors.
- `NodeOutput::Clear(PinId)` (WIT `clear`, SDK `Output::Clear`) removes a data output from the cache, invalidates pure results like a data write, and omits the cleared pin from traces. Skipping an output still keeps its previous value. A connected source without a value gives optional inputs no value and silently blocks required inputs.
- A data input has one source: `connect_data` replaces the previous connection. `connect_exec` validates pins too.
- An unconnected data input (number/string/bool/any, enum) can get a value right on the node: `ClientMessage::SetInputValue`, `TickEngine::set_input_value`. It is stored among the properties as `in:<pin id>` (`input_value_property`) but is not passed to the node: `pull_inputs` substitutes it while nothing is connected. Values that no longer fit after a pin change are removed in `set_node_property`. Works for plugins too.
- **Input variable bindings.**
  An unconnected data input can read a variable instead of an inline value: `ClientMessage::SetInputVariable`, `TickEngine::set_input_variable`.
  It is stored as property `var:<pin id>` = `DataValue::String("var.<name>")` (`input_variable_property`, `input_variable_pin`) and is never passed to the node.
  Setting a binding removes an inline value on that pin, and setting an inline value removes the binding.
  An active wire connection takes precedence over the binding while connected.
  During execution, `pull_inputs` resolves the variable through the node's sheet and converts it via `TypeRegistry::compatible` or `TypeRegistry::convertible`.
  Missing variables or failed conversions provide no value: optional inputs see none, while required inputs block execution and log one error until recovered.
  Bindings survive graph export/load, snippets, stubs, undo/redo and settings paste.
  In the editor, typing a reference (`var.x`, `sheet.x`, `global.x`) in an unconnected input's inline field binds the variable, while String inputs accept quoted `"var.x"` for literal text.
  Bound inputs display a chip with the reference and a clear button; clicking the chip text re-opens the inline field for editing.
- **Split struct pins.** `TickEngine::set_pin_split(node, pin, bool)` stores `split:<pin>` = `Bool(true)` alongside `in:*`; neither is passed to the node. `node_definition`/`NodeInstance` expose effective field pins. Output fields project the original cached/pulled struct; input fields assemble a tagged object, with non-optional fields required and optional missing fields omitted. Splitting removes original connections; recombining removes field connections and inline field values. Graphs, snippets and stubs preserve split settings. Protocol: `SetPinSplit { node, pin, split }` → disconnect events and `NodeUpdated`. Virtual ids are `0x8000_0000 | (original_pin << 8) | zero_based_field_index`; the range `0x8000_0000..=0xbfff_ffff` is reserved (native registration rejects it; plugin definitions discard reserved real pins with a warning). One level only: original ids ≤ `0x3f_ffff`, 1–256 fields; append fields to preserve ids. Nested struct fields can still connect to explicit `object/make` / `object/break` nodes. Struct pins sharing an id across directions split together; other pins with that id are unchanged. The editor uses the existing row height and socket positions, with indented field labels and split/recombine buttons; Match retains a name/type row above its split fields.
- **Media types.**
  Core-owned `media.*` named struct types (`media.photo`, `media.audio`, `media.video`, `media.document`) are registered by the engine at construction.
  The `media.` prefix is reserved from plugin registration, and plugins attempting to register types under this namespace are rejected.
  All four media types share the same minimal, append-only field layout: optional `url` (String), `file_id` (String), `mime_type` (String), `file_name` (String), `size` (Number, bytes), `width` (Number), `height` (Number), `duration` (Duration), and `blob` (String).
  Media values are reference descriptors without raw byte payloads.
  A media value is considered valid only when `url`, `file_id` or `blob` is set, and consumers report translated errors otherwise.
  Core-owned media structs are covered by universal object nodes `object/make` and `object/break` without cluttering the built-in node registry.
- **Plugin-defined data types.** `DataType::Named("ha.state")` refers to a `TypeDefinition` (`title`, `color` `#rrggbb`, `TypeKind::Struct { fields: FieldDefinition { name, title, description, data_type, optional } }` | `TypeKind::Enum { values }`). The name contains a dot (`is_type_name`) and is written as-is in text (`parse_data_type`/`data_type_name`, `*_type` properties, Match inputs). A struct value is `DataValue::Object` with `type_name: Some(..)` (`get_type()` → `Named`; `#[serde(default)]` without `skip_serializing_if`, since postcard is not self-describing); an enum value is a `DataValue::String` from the list (validated by `text::parse_value_in` / `input_value_fits`). The registry is `TickEngine::types` (`TypeRegistry`); a plugin adds its types atomically, and a name clash or an unknown type in a field or pin fails the plugin load. Exact pin compatibility goes through `TypeRegistry::compatible` (the free `types_compatible` knows only `Any`): `Named(a)→Named(a)`, `Named↔Any`, `Named(struct)→Object`, `Named(enum)→String`; never `Object→Named` or `String→Named` as exact matches. Connections also accept `TypeRegistry::convertible`: String ↔ Number/Bool/Time/DateTime/Duration/Color, Number ↔ Bool, and String → named enum (exact member value only). Lists convert element by element, with the whole conversion failing if any element fails. Structures are never implicitly unpacked. Compatible connections keep their existing behavior (including Any and enum → String); converting wires are dashed and show translated source/destination types. **Add new struct fields only at the end**: pins are positional in `object/make` / `object/break`. In Match a struct behaves like an Object (`condition::ops_in`), an enum offers `=`/`≠`/`has value` with a drop-down of values. A plugin node may not put an object with a foreign or missing tag on a `Named` output: the host drops the value and logs an error.
- **Universal struct nodes.** Universal pure native nodes `object/break` ("Break object") and `object/make` ("Make object") decompose and construct any registered struct type (category `Data`, cost 1, `ticknode-core/src/builtin/objects/`).
  Both nodes share the persisted `type` property (Select over registered struct types, empty = unconfigured).
  `object/break` has input 0 "Value" (`Any` when unconfigured; `Named(<type>)`, required when configured) and field outputs 1..=N, omitting missing optional fields.
  `object/break` adapts to a source struct wire connected to input 0 (`adapts_on_connect(0)`), declining non-struct types.
  `object/make` has field inputs 1..=N (required for non-optional fields) and output 0 "Value" (`Named(<type>)`).
  The engine updates node type snapshots and bumps `definition_revision` via `Node::types_changed`; surviving snapshots preserve pins and wires if a plugin is disabled.
  The field snapshot is persisted in the hidden `fields` property and used when the type is not registered at load.
- **Opaque identifiers.** Appended `TypeKind::Identifier { labels: Option<String> }` (WIT `type-kind::identifier`, SDK `TypeDefinition::identifier(name, title, description).labels(source)`) stores only `DataValue::Number(NumberValue::Int(i64))`. Identifiers connect only to the same named type or Any, with no Number/String/foreign-ID conversions. Plugin output checks reject other representations, recursively in declared lists/struct fields. Match offers equality, inequality and presence, uses exact integer parsing/comparison, and rejects ordering and foreign identifier contracts. Inline values accept signed decimal IDs; labelled types use the searchable picker (including typed IDs). `TypeDefinition.plugin` is appended host-assigned ownership metadata, independent of the dotted name; it selects the owner's dynamic option source. Labels use decimal option values: the editor shows `Name (id)` in inline values, variables, wire labels and traces; unknown IDs show their decimal text. Shared `to_text::IdentifierLabels` and `to_text_with_identifiers` inject lookup without a core dependency; native To text and template `text.<input>` resolve live `OptionStore` labels to the name alone, falling back to the exact ID. Typed variables preserve identifier contracts when read or written.
- **Physical quantities.** Core-owned `quantity.*` named types use the appended `TypeKind::Quantity(QuantityKind)` variant; values remain canonical `DataValue::Number` (no ABI/layout change). `ticknode-shared/src/quantity.rs` and `quantity/{catalog,catalog_extra,currencies,indices,parse,format}.rs` define a catalog covering HA sensor classes, unit factors/offsets/aliases and affine, inverse or logarithmic curves (`UnitCurve`, appended with an Affine default), registry-aware parsing, significant-digit or per-quantity fixed-decimal defaults (`QuantityKind.decimals`) and the public `unit_by_symbol` / `to_canonical` / `from_canonical` helpers (SDK re-exports `quantity`). The engine registers the catalog at construction; `quantity.` and the quantity kind are reserved from plugin registration, and WIT still only declares structures/enums. Quantity → Number is compatible; Number/String → quantity and quantity → String convert, while different quantities never convert or compare directly. Currencies have separate `quantity.currency_<code>` types (no exchange rates), money defaults to two decimals (JPY/KRW/HUF: zero), and Beaufort/AQI/pH have their own types. Color temperature uses canonical kelvin with inverse mired; energy per distance combines consumption and inverse efficiency units; signal strength uses canonical dBm with logarithmic mW/W. Auto ladders and default thresholds use only affine units. Data size includes decimal and binary units through YB/YiB. Canonical text for persistence/logs remains a bare number. `Conversion::apply_with_display` supplies project rules and formatting locale (including nested lists); core labels come from cached simple embedded Fluent `unit-*` / `number-decimal-separator` messages in `ticknode-core/src/quantity.rs`.
- **Text conversion and quantity editing.** Pure adaptive `text/to_text` (String category, "To text") converts every value type, with required Value input 1 (default Any) and Text output 0. A connection adapts its `value_type`; `AddNodeConnected` adapts before broadcasting. Persisted properties are `value_type`, `show_units` (yes/no), `unit` (auto/fixed), `rounding` (project/significant/decimals), `digits` (empty = selected mode default; significant 1–15, decimals 0–15; legacy digits imply significant), `locale` (server/en/uk), `true_text`, `false_text`, `datetime_format`; only relevant controls appear (`to_text::property_visible` also drives editor geometry). `ticknode-shared/src/to_text.rs` shares quantity presentation with converting wires, recursively handles lists and declared struct fields, and formats date-times in the server local zone. `ServerSettings.display: DisplayRules` is an appended defaulted field: sparse per-quantity overrides of ordered `UnitStep { from, unit }` thresholds in canonical units and rounding mode (significant digits or fixed decimal places). The appended number rule defaults to Significant/3. Missing entries derive the catalog auto ladder (first threshold zero) and rounding defaults (`decimals` when specified, otherwise three significant digits); significant rounding uses rounded absolute magnitude to select a step, while decimals use raw magnitude. Shared validation rejects unknown quantities/units, invalid digits, nonfinite/unordered thresholds and step counts outside 1–8 before applying settings. The engine keeps rules with its locale and clears pure results on changes. Editor Settings → Units and formatting (`home/settings/display{,/logic}.rs`) edits thresholds in each step's unit through the engine Save/Reset flow. All quantity displays and inline initial units use current rules with the UI locale. Constant persists an optional quantity `value_type`; Match accepts typed literals such as `p > 2 kW`; a constant on a quantity input is kept as written (`"68 °F"`, `quantity::parse_literal`/`literal_text`) and compared canonically. The Match editor's constant field for a quantity input has a unit drop-down (`InlineValue unit_literal`), keeps that unit across edits (`operand_fits` accepts literals) and shows it in case labels. Built-in `compare` adapts A/B to a connected quantity like math nodes. Inline number/unit controls commit lossless canonical values. HA and weather use these quantity types.
- **Plugin quantities.** `ha-plugin/src/units.rs` maps HA units through the SDK quantity catalog, trying recognized `device_class` quantity candidates before unambiguous symbol lookup and keeping integration aliases local. Monetary classes select currencies by ISO code; wind speed also accepts Beaufort, and energy distance maps consumption and inverse efficiency units to `quantity.energy_consumption`. Unitless AQI/pH classes use their sole unit; typed outputs still require finite numbers. `ha/entity` infers/selects any catalog quantity, and duration sensors map to `Duration`; Value/Previous convert each state's own current unit to canonical numbers, clear incompatible/missing units (except unitless `aqi`/`ph` classes), and warn once per node until recovery. Unit stays raw; `ha.state` stays unchanged. Action number selectors with mapped units and `color_temp` selectors (kelvin or default mired) snapshot quantity pins plus an appended positional `field_units` property; absent metadata defaults to no unit, preserving legacy Number fields. Execution converts canonical inputs back to the snapshotted unit and rejects non-finite conversion results. `http/weather` Temp is `quantity.temperature`, and its text API expects Celsius. Math/string/delay plugins retain their existing types; quantities feed math as canonical numbers.
- **Required inputs.** `PinDefinition::required` (`serde(default)`; WIT `pin.required`; SDK `data_in(..).required()`). An input is set when a source is connected or, for text types and enums, a value is set on the node (`in:<pin>`); struct/list inputs need a connection. A node with an unset required input does not run (a pure node yields no value, an active node's `execute` is not called) and logs an error once until the state changes. A connected source without a value is skipped silently. In `object/make` the required inputs are the non-optional fields. The editor highlights such a pin and node as Error (`Editor::required_missing`).
- `match` is a decision combinator. Properties: `inputs`, a list of `"<pin>:<name>:<type>"` (type `any` = "auto"), and `cases`, a list of `"<pin>: a > 10 and b != \"on\""` (parsing, evaluation and display live in `ticknode_shared::condition`; `and` binds tighter than `or`). Operators depend on the left input's type (`ops_for`: comparisons for numbers/time/duration, `contains`/`starts_with`/`len_*` for strings and lists, `has_field` for objects, unary `is_true`, `is_empty`, `has_value`, …); the right side is a constant or another input, and a constant is coerced to the input's type (`text::coerce_to`: `"07:30"` → time). A graph without `inputs` is the old format: inputs are derived from the names in conditions (Any, pins 1.. alphabetically), but only during `create_node`; after `Node::restored` the inputs are explicit, both in a new and in a loaded node. Each case is an exec output with a stable pin number; Else is pin 0. There is no separate Branch node.
- **Tick durations.** `DataValue::Ticks(u64)` is the last value variant and shares `DataType::Duration` with wall-clock `Duration`. `DataValue::Duration` is a signed `chrono::TimeDelta` serialized as `{secs, nanos}` with floored seconds and non-negative nanos. Text accepts `10t`, `10 tick(s)` and Ukrainian `такт`/`такти`/`тактів` (case-insensitive), and formats ticks as `10t`. Match compares ticks with ticks and signed duration with duration; all mixed ticks/time equality and ordering operators, including `!=`, return false because Match has no tick clock.
- **Delay inputs.** Built-in `sleep` has exec In (0), Duration Delay (1), exec Out (4); the old UseTicks/TickDuration pins are removed. Plugin Queue/Ignore/Reset Delay keep their pin IDs and take one Duration Delay input. Missing values wait one tick; non-positive durations act as zero (firing on the next possible tick). `HostState::ticks_for_value` and SDK `host::delay_for` accept ticks or time, rounding time up and treating negative delays as zero; WIT still takes ticks. Clock is unchanged.
- **Adaptive nodes.** `NodeDefinition.adaptive` advertises native adaptation (`false` for plugin definitions; no WIT field). `Node::adapt_to(pin, type)` changes persisted properties; `TickEngine::adapt_node` follows the property edit path, reconciling caches, roles, signatures, inline values and connections. Constant adapts output 0 with `text::default_of` (Duration defaults to one second). `Node::adapts_on_connect(pin)` opts an input into adapting when a data wire is connected, only while the node's other data inputs are unconnected (To text Value; built-in `math/add|sub|mul|div` A, and B for Add/Sub); a declined type falls back to ordinary validation. Math nodes accept only Number or a core quantity, persist `value_type` only when it is not Number (hidden on the node, like Constant's), keep it on A/B/Res for Add/Sub, and on A/Res with a plain-number B for Mul/Div. `AddNodeConnected` adapts before connecting and emits the adapted `NodeAdded` in the same history entry.
- **Text templates.** Pure native `text/template` (String, "Text from template") uses pinned MiniJinja with fuel (10,000 instructions per render) and its default recursion limit. Pure template analysis, syntax validation, input variable derivation, `DataValue` conversion, fuel-bounded rendering and `template::complete` (pure caret completion distinguishing DateTime/Time/Duration kinds: variables, struct fields via TypeRegistry, text., loop., filters, tests, tag keywords, functions) live in `ticknode_shared::template` (`variables`, `validate`, `CompiledTemplate` (parsed once, kept by the node), `render`, `plain`, `TemplateError { message, line, column, range }`), shared between the server and editor. A new node starts with the template `{{ value }}` (one Any input) and is adaptive, so the wire menu offers it for any data wire; stored templates, including empty ones, are restored as written. The Multiline `template` property derives optional Any inputs from undeclared variables in source order (built-in globals excluded); renaming a single variable in place keeps its pin. Hidden `pin_ids` stores active `"<id>:<name>"` entries; `next_pin` is a persisted monotonic allocation cursor, so deleted IDs are never recycled, including after reload. Restoration reconciles the mapping after all properties are applied. Interactive syntax validation and runtime rendering failures use structured `error-template-syntax` / `error-template-render` messages from core locales; runtime logs are English, once until recovery. `NodeContext::input_types` supplies connected source contracts. Inputs are plain MiniJinja values, preserving standard arithmetic, comparison, test and filter behavior. The reserved global map `text` exposes `text.<name>` as the input formatted exactly like To text with the declared source type, project rules and engine locale, including units in lists and struct fields; static `text.<name>` references also derive that input pin. The name `text` is excluded from input derivation and must not be reassigned in templates. The separate `| text` filter formats runtime kinds only (plain-number rules, localized booleans, recursive lists/maps, unchanged strings); quantity units come from `text.<name>`. Dedicated `date(pattern)` (readable tokens and locale presets from Fluent `text-date-format-*`, month/weekday names `text-month-*` / `text-weekday-*` with a CLDR format-context month form) and `strftime(format)` filters exist (`ticknode_shared::template::dates`) for date-times and times in the server time zone. Dedicated `plural` filter (`ticknode_shared::template::plural`) uses CLDR cardinal rules via `ticknode_shared::plural` (mapping positional forms to `integer_categories` and supporting keywords zero/one/two/few/many/other with `#` replacement) and resolves localized text through `QuantityLabels::{locale, message_args}`. The built-in `now()` global function returns the current UTC instant as an RFC 3339 string. Dedicated `ago` filter (`ticknode_shared::template::ago`) renders relative time into natural text using CLDR plural forms and engine quantity labels. Dedicated `duration` filter (`ticknode_shared::template::duration`) formats wall-clock durations into compact units ('short'), spelled-out plural words ('long'), or pattern tokens ('H:mm'). Dedicated `unit([symbol], digits=, decimals=, units=)` filter (`ticknode_shared::template::unit`) formats numbers and physical quantities like To text; `CompiledTemplate::new` scans expressions via `minijinja::machinery::tokenize` for static dotted paths (ignoring local `set`/`for` variables) and rewrites the compiled template to pass `__path`, keeping a list of insertions to map render-time error ranges, lines and columns back to the original source; at render time `render_localized` resolves input and struct field declared types through `&TypeRegistry` and delegates formatting to `RenderEnv.to_text`. Missing values are undefined; date-times use RFC 3339 and time/duration/color use canonical text. Whitespace control is configured by the described Select property `blocks` (`keep` by default, omitted from persistence; `trim` sets `trim_blocks` and `lstrip_blocks` via `TemplateOptions` to strip trailing line breaks and leading indentation around tag lines). Template braces in Fluent help use string-literal placeables. In the editor, `template` is edited in place on the node (`TemplateField`) with caret completion (`TemplateCompletionLayer`, `template::complete`, distinguishing DateTime/Time/Duration kinds), live syntax errors (`st-error`), debounced commits (deriving pins while typing) and live rendering preview with trace/inline inputs in an extra fixed status row. The editor field wraps an underlying syntax highlighting layer (`TemplateHighlightLayer`, `template::highlight`) rendering token-classified spans with an overlaid error range, synchronized scrolling, and theme CSS tokens.
- **Convert node.** Pure adaptive `convert` uses the directional catalog in `ticknode_shared::convert`; Value input 1 adapts on connection, Result output 0 follows the selected `target`, and `unit` appears only for quantity/number conversions. Persisted `value_type` is hidden; shared `convert::property_visible` also drives editor geometry. Invalid conversions yield no value. Property option labels fall back from node-specific Fluent keys to translated type titles (`quantity:<name>` or known type names), then `unit-<slug>` symbols for `unit`, then the definition label.
- **Hysteresis.** `logic/hysteresis` is an active adaptive Schmitt trigger (Logic, cost 1). Required Value/On threshold/Off threshold inputs share persisted `value_type` (Number or core quantity, hidden on the node); connecting Value adapts the type while preserving inline thresholds. Persisted `mode` is `rising` or `falling`, with strict comparisons and state retained at equality and inside the dead band. Every evaluation emits State, then transition-only Turned on/Turned off, then Out. Invalid threshold order preserves state and reports a translated node error, logging once until recovery. State starts off and resets after restart or node recreation.
- **RS trigger.** `logic/rs_trigger` is an active bistable flip-flop (Logic, cost 1).
  Exec inputs `Set` (0), `Reset` (1), and `Toggle` (2) change the state via pulses, while `Evaluate` (5) re-evaluates level inputs.
  Optional Bool data inputs `S` (3) and `R` (4) act as level inputs sampled on every execution.
  Persisted Select property `priority` (`reset` default, or `set`) resolves conflicting active inputs, including Set and Reset pulses arriving in the same tick.
  Persisted Select property `initial` (`off` default, or `on`) sets the state after creation or restart.
  Every evaluation emits Bool data `State` (0), transition-only exec `Turned on` (1) or `Turned off` (2), and exec `Out` (3).
- **Date and time nodes.** Pure built-in nodes (category `Time`, cost 1) interpret dates in the server local time zone (`chrono::Local`) and obtain time through `HostState::now()` (which supports `clock_override: Option<DateTime<Utc>>` for testing, never calling `Utc::now()` directly in nodes).
  `time/now` outputs UTC date-time and local time of day.
  `time/difference` computes `Result = A − B` for adaptive DateTime or Time inputs (plain difference without midnight wrapping for Time).
  `time/shift` computes `Result = Value ± Duration` with `operation` (`add` / `subtract`), wrapping around midnight for Time and performing checked arithmetic with translated `error-time-shift-overflow` for DateTime.
  `time/break` extracts local Year, Month (1–12), Day, Weekday (1 = Monday … 7 = Sunday), Hour, Minute, Second, Time of day, and Day of year.
  `time/start_of` computes the local start of minute, hour, day, week from Monday, month, or year converted to UTC, with DST gap recovery.
  `time/in_range` checks `From ≤ t < To` with midnight crossing when `From > To` and empty range when `From == To`, falling back to `host.now()` when Value is unconnected.
- **Download media (`media/fetch`).**
  Active built-in node (category `Network`, cost 50, title "Download media").
  Exec input `In` (0) initiates the download.
  Data input `URL` (1, String, required) specifies the HTTP/HTTPS endpoint and supports basic auth in the URL.
  Data input `Headers` (2, String, optional) accepts newline-delimited `Name: value` HTTP headers.
  Persisted Select property `kind` (`photo` default, `audio`, `video`, `document`) selects the target media type.
  Outputs are exec `Done` (10), exec `Failed` (11), data `Error` (12, String), and data `Media` (13, `media.<kind>`).
  Uses host HTTP with save-to-blob streaming semantics; native nodes may reach any host without capability checks.
  Successful downloads populate `blob`, `mime_type`, `size`, and `file_name` on the `Media` struct.
  Success clears the previous Error output, and failure clears the previous Media output.
  Runtime failures also report translated node errors through `UiMessage`; Error pin data and logs remain English.
- The text form of values (fields on nodes, conditions) is `ticknode_shared::text`: `parse_value(text, &DataType)` / `format_value`; time `HH:MM[:SS]`, date-time `YYYY-MM-DD HH:MM`, duration `90` / `1h 30m` / `500ms`, color `#rrggbb[aa]`.
- **Property schema and validation.** `NodeDefinition.properties: Vec<PropertyDefinition { name, title, description, kind, input }>` (`ticknode-shared/src/property.rs`; WIT `property-definition`; SDK builders) describes stored properties without changing their persistence format. Appended kinds are `Duration { signed }` (text, empty = unset, wall-clock units or `HH:MM:SS`, optional sign for signed offsets), `Time` (text `HH:MM[:SS]`, empty = unset), `MultiSelect` (comma-separated values normalized to schema option order), `Multiline` (free text textarea), and `Hidden` (persisted but never displayed or counted in geometry). Text/Select/Dynamic retain their existing contracts; Select validation remains the node's responsibility. Interactive `set_node_property` validates typed kinds through shared `property::normalize_property_value`, then calls `Node::validate_property(&self, name, &DataValue) -> Result<(), UiMessage>` before mutation. Plugin nodes expose the matching WIT `validate-property` and SDK `PluginNode::validate_property` hook (default Ok); plugin error keys are restricted to the same namespace as configure. Rejections return `EngineError::InvalidProperty` without modifying the graph. `SetProperty` replies to the initiator with its stored `NodeUpdated` before the error; property drafts observe these updates even when the value is unchanged. `AddNodeWith` uses `create_node_interactive` to validate each property before insertion, then calls `restored` after all properties just like normal construction; a rejection never adds a node. Graph/snippet loading, settings paste, undo/redo, and plugin recreation restore stored state without validation. HA action's scalar `supports_response` snapshot is Hidden; HA entity has no internal scalar snapshots.
- **Property or input.** Appended `PropertyDefinition.input: Option<PinId>` (WIT `property-definition.input`, SDK `.or_input(id)`) marks a property that can use a data input instead. The engine omits that input from effective definitions whenever the property is nonempty; interactive edits prune its wires and inline values. Base signatures retain the declared contract. The editor hides the property row while its input is connected, including width/height and resize allocation, and omits a duplicate inline value on the input. Dynamic pickers put the translated `property-from-input` empty choice first. `ha/action.target` uses Entity input 1; input mode offers all actions and preserves field snapshots when switching from a selected target. Legacy graphs with both a target and an Entity wire keep the selected target and preserve the wire as a visible detached connection during load, paste, undo or plugin revival. `ha/entity` has no duplicate Entity input and remains a subscription picker; triggers and conditions likewise have no duplicated property/input pair.
- **HA property forms.** Trigger offsets and condition sun offsets are signed Duration properties; template For is unsigned Duration; condition time boundaries are Time and weekdays are MultiSelect. Event data, templates and conversation commands are Multiline. Trigger At is a Dynamic picker over `time_entities` (input_datetime and timestamp sensors), also accepting typed HH:MM[:SS]. `ha-plugin/src/validation.rs` shares validation between interactive edits and restored configurations (JSON objects, MQTT filters, IDs, clock patterns and typed fields). Invalid stored trigger/condition settings raise translated runtime node errors; English logs are throttled until recovery. Sun offsets become Hidden in each instance when their boundary is none, retaining stored values; WASM definition refresh increments `definition_revision` and updates polling roles after property edits. HH:MM:SS durations retain fractional seconds as well as legacy -30m and comma-separated weekdays.
- **Editor property rows and width.** Described properties appear in definition order before undescribed properties (which retain stored order). Hidden properties are excluded for all value types. Only undescribed `*_type` properties use the DataType heuristic. Duration properties use wall-clock number/unit controls (minutes by default for signed offsets), a short numeric placeholder and a compact localized earlier/later sign toggle while preserving sub-millisecond offsets; Time validates locally, MultiSelect uses scrollable toggle chips, and Multiline participates in resize allocation. Option labels use the existing property Fluent keys. `NodeLayout` estimates translated property and paired pin labels using the bundled Cascadia Code advance (1200/2048 em at 12 px), reserves field space, and clamps automatic width to 240–480 px (Match minimum 400 px). CSS and wire anchors use this same width and per-row pin budgets; stored user sizes keep precedence. HA trigger/condition properties also return in definition order. Compact Select/Bool controls and duration/quantity unit selectors retain intrinsic width at the right edge. Labels have no width cap and take space before text fields; text and number fields reserve 18 DU and grow with the node. Geometry estimates include the translated header title and category badge (title takes priority at the width cap), translated labels, selected select options, split controls and the same field minima. Compact selects use selected-option content sizing with a measured fallback and a 160 px cap. MultiSelect chips use optional `...-option-<value>-short` Fluent labels (first three characters otherwise) and full option tooltips; the width estimate reserves all chips.
- **Dynamic options.** A plugin publishes `PropertyOption { value, label, detail, icon: Option<"mdi:name"> }` lists with the host function `set-options(source, options)` (SDK `host::set_options`), callable from any plugin call (`configure`, `plugin-tick`, `execute`); it replaces that source. Limits: 20 000 options per source, 256 sources per plugin (including entity domain lists and target-domain unions), 512 bytes per string (an over-long or empty-valued option is dropped, an English warning goes to the node log). The store (`OptionStore` in `plugin.rs`) lives in the plugin `Runtime`, so it survives a crash, and is cleared on disable. `TickEngine::property_options()` feeds `Init.property_options`; `take_property_option_changes()` returns only sources whose list changed (a disable reports them as empty lists), and the actor broadcasts `ServerMessage::PropertyOptions { plugin, source, options }` after every tick and every command. An empty list removes the source in the editor (`Editor::property_options`, keyed by `(plugin, source)`).
- **Property picker (editor).** `picker.rs`: `PickerField` is the field on the node (current value as icon + label, raw value if the list lacks it); clicking it sets `Editor::picker`, and `PickerLayer` (mounted at the app root, `position: fixed`, so it renders above the transformed canvas) shows the popup: search box (case-insensitive terms over label, detail and value), at most 100 rows (`MAX_ROWS`), up/down/Enter/Esc, Enter with no match (or the "Use ..." row) sets the typed text, `placement` opens it upwards near the bottom and clamps it on narrow screens. It sends `SetProperty` like other property editors and closes on a press outside, camera change or node removal. Icons are Material Design Icons (`@mdi/font`, bundled in `ticknode-editor/assets/mdi/`, license in `LICENSE-MDI.txt`; no CDN): `mdi:xyz` renders as `<span class="mdi mdi-xyz">`.
- Node positions belong to the server, not the engine; they are written into `NodeModel.position` only when saving.

Media Fetch rejects invalid Kind edits before changing its properties or output type.

## Plugin namespace paths

Templates reserve every accepted plugin namespace as a global, so `{{ ha.light.kitchen.attributes.brightness }}` creates no HA input pin.
`{{ text.ha.sensor.power.state }}` formats the declared field type using project units and engine locale, and `{{ ha.sensor.power.state | unit }}` uses the same contract.
Only static entry paths are watched; dynamic entry selection such as `ha[name]` is outside the namespace contract.
Missing or unavailable fields are undefined, with the same rendering behavior as missing variables.
Formulas accept dotted paths such as `ha.sensor.power.state * 2`, retain quantity inference, and report existing translated variable errors when unavailable or non-numeric.
Input `var:<pin>` properties and `SetInputVariable` also accept full plugin paths such as `ha.sensor.power.state`.
These bindings are read-only, persist with the graph, and yield to connected wires.
Formula nodes share immutable catalog indexes and look up only their referenced namespace field types, including after formula edits.
The editor stores slim namespace catalogs, a per-entry field cache invalidated on namespace replacement, and sheet value telemetry; completion, lints and preview integration are deferred to task B.
